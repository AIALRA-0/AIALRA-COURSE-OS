# 分阶段生成恢复与局部修复

## 问题与依据

旧版计划式生成每页只有一次共享修复机会，且未持久化已验证的中间阶段。最近四个候选页面分别因覆盖引文不匹配、总结中的数学定界符不完整、规划事实缺少覆盖声明、覆盖引文不匹配而失败。它们的费用已计入任务估算，但没有产生可用新页面。现有线上任务的阶段正文未保存，因此不能从这四次历史调用直接恢复正文，也不能把新代码的离线测试冒充线上成功。

参考 ReadWeave 当前的主动研究与局部修复做法：检查结果只授权修改明确位置；保留已正确的正文和来源；提交前核对旧内容与摘要；修复后重新验证全部依赖。宽泛质量建议不能授权整篇重写，无法安全完成的修复不能伪装为通过。Course OS 仅移植这些处理原则，不复制 ReadWeave 的提示词、数据或状态。

## 当前实现

生成计划、开篇、讲解、总结依次通过验证后写入私有运行状态。恢复点绑定课程版本、页面来源、前页讲解、教学蓝图、写作策略和提示词快照；摘要不符时停止复用。失败阶段的候选字段和具体问题也保留，下一次只继续这一阶段的局部修复。生成任务接口不会返回恢复点正文。

检查结果被转成字段修复单。覆盖问题只准改覆盖声明，并保护无关原子已有声明；数学问题定位到出错字段；文字字段补丁必须是有限范围的变化。提交器核对字段摘要、返回字段范围和变更大小，应用后重新执行结构、覆盖与数学验证。每个阶段最多两轮局部修复，不能借重试重新生成已通过阶段。

错误事件区分供应商额度或限流、输出结构、教学内容、存储读回、配置和未知错误，并记录可采取的恢复动作。额度不足应切换已授权路线，暂时的供应商或存储故障应恢复当前阶段；来源缺失或配置错误需要保留断点并呈现真实问题，不能捏造成功内容。

## 四页对照范围

| 历史样例 | 旧版真实结果 | 新版离线回归路径 |
| --- | --- | --- |
| 页 4：覆盖引文不匹配 | 失败 | 仅修复覆盖声明，保留讲解正文 |
| 页 7：讲解已修复，随后总结数学定界符失败 | 失败 | 两个阶段各有修复机会，第二次只修总结字段 |
| 页 12：开篇先修复，随后规划事实缺少覆盖声明 | 失败 | 开篇修复不耗尽讲解阶段的修复机会 |
| 页 16：覆盖引文不匹配 | 失败 | 仅修复覆盖声明，保留其他声明与正文 |

这些对照使用真实失败类型构造的合成内容，四条路径在自动测试中通过。历史失败任务没有可恢复的阶段正文，因此尚未做真实模型的四页续跑，也没有扩大生成或改动正式课程。上线前仍须复核任务状态、磁盘、回滚镜像和候选版本，部署后不得自动重试这四个历史任务。

## 继续扩大生成的条件

本地测试、类型检查、构建、公开内容扫描和远端健康检查通过后，先观察一个**新任务**在真实模型下的阶段存储、局部修复、费用归属和读回；它不得触碰历史四页任务或正式课程。实际页面质量和费用满足目标后，再增加样例数量。结构测试通过不能替代用户阅读验收。
