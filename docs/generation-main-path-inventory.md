# Course OS 单页生成主路径盘点

基线：`796e360af0ab3b275d887ecf693f884c1245401f`

## 当前实际路径

上传与离线转换 → 每页建立任务 → Worker 领取 → 读取来源页和页图 → 按换行建立文字区域及覆盖要求 → 建立教学蓝图 → 模型生成并校验计划 → 分别生成并校验开头、完整讲解、总结 → 为各阶段执行最多两轮局部修复 → 等待前页核心内容 → 单独生成并校验承接段 → 再做内容检查、覆盖检查、叙述检查、语义模型审计及修复 → 编译页面 → 发布质量检查 → 写入草稿并读回 → 更新任务状态

`planned-teaching.ts`、`app.ts` 中还分别存在修复与失败重试路径；中间结果错误可能重新进入任务队列，却没有产生新的模型修复调用

## 保留

| 能力 | 原因 |
| --- | --- |
| 原页图、离线文字和来源引用 | 教学模型必须知道课件实际内容，来源仍可追溯 |
| 写作策略全文、教学顺序与现有页面栏目 | 已有高质量样例依赖这些教学要求 |
| 简短的教学规划 | 保留先思考教学路径的收益，不用严格中间格式 |
| 最终页面结构、确定性排版、一次格式局部修复 | 页面必须可读取，修复只作用于最终成品 |
| 按页任务、幂等、成本和阶段耗时 | 真正的故障恢复和并发观测仍需要这些信息 |
| ReadWeave 草稿写入与读回 | 保证用户能打开已完成页面 |

## 移出在线阻断路径

| 机制 | 处理 |
| --- | --- |
| 教学内容评分、术语和来源完整度检查 | 用于离线样例评估和线上诊断，不阻止可读取的页面 |
| 覆盖率、证据引用和发布质量检查 | 继续记录可核对信息，不以 OCR 行为强制教学义务 |
| 语义模型审计 | 按需离线评估，不在每页主体生成后串行调用 |
| 承上启下 | 主体页面交付后补写，只依赖前页已完成主体 |

## 删除或替换

| 当前机制 | 原因与去向 |
| --- | --- |
| `sourceTextRegions` 的逐行原子及 `requiredFields` | PPT 换行和页码不是知识边界；保留原文字作为信息 |
| `teachingPlanSchema` 的事实、原子、问题强绑定与计划修复 | 计划只作写作辅助，不作业务事实源或阻断合同 |
| `opening`、`explanation`、`consolidation` 三段模型串行生成 | 改成一次完整教学生成 |
| 阶段内两轮内容修复、覆盖修复、语义审计复查循环 | 最终格式问题最多局部修复一次；内容质量只观测 |
| 失败后无新模型调用的整阶段重复执行 | 仅针对真实暂时性故障重试，复用已持久化的页面结果 |
| 所有页面共享的 PostgreSQL JSONB 行锁 | 生成任务状态独立写入；不重建无关存储体系 |

## 验收边界

默认单页模型请求最多三次：页面视觉理解（确有需要时）、简短规划、完整教学页；最终格式错误最多额外一次局部修复。页面 A 的状态写入不能阻塞页面 B。记录实际并发模型请求、各阶段耗时与成本。用户能够在主体完成后立即阅读，承接段随后补齐。内容质量检查不进入在线阻断路径

## 实施后的删除清单与验证

- 删除旧在线模型路由器及紧急双轨入口，所有已配置供应商共用同一完整教学页生成路径
- 删除教学蓝图构造、蓝图校验、逐行强制覆盖、在线语义模型审计、独立字段修复循环与对应旧提示词文件
- 删除开头、正文、总结分段生成及失败后无新模型调用的整页自动重入队；短计划不再是格式合同
- 每页任务状态和事件写入自己的 PostgreSQL 行；聚合计划更新仍在任务结算时进行
- 新集成用例同时启动六类页面，断言至少两个实际模型请求重叠、每页默认两次模型请求、格式修复不超过一次，草稿可读且页脚没有成为覆盖义务
- 隔离 PostgreSQL 库实测：页面 A 持有任务行锁 8 秒时，页面 B 写入耗时 587 毫秒。线上模型耗时、成本和教学质量另以候选实跑记录，不用模拟用例冒充真实结果
