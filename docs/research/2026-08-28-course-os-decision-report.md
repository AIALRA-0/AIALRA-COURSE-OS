# Course OS 决策报告

**核验截止日期：2026 年 8 月 28 日**  
**决策性质：产品、学习科学、软件架构、安全与竞争研究；不构成法律意见，也不是完整的专利自由实施分析。**

证据标签：

- **[confirmed]**：有直接来源、代码、许可证、论文或官方文档支持。
- **[inferred]**：由多项证据推导出的工程或产品判断。
- **[hypothesis]**：合理，但必须通过本项目实验验证。
- **[unknown]**：目前没有足够证据下结论。

本次调查覆盖 problem、mechanism、product、code、research、adjacent、failure 和初步 patent 八个分支，但不声称覆盖全部市场，也不声称项目绝对原创。

## 1. 一页执行结论

### 决策：**REFRAME——重新定义后有条件推进**

不是暂停，也不是直接建设完整系统。

应把项目从：

> “自动生成教授级完整课程的多 Agent 教学平台”

重新定义为：

> **一个以不可变来源、机器可检查解释覆盖、形成性测验和长期掌握记录为核心的课程学习编译器与播放器。**

### 为什么值得推进

**[confirmed]** 当前市场已有三类方案：

1. OpenMAIC、instructional_agents 等自动课程生产系统；
2. Gemini Notebook、Khanmigo、Coursera AI 等材料问答或辅导产品；
3. Moodle、Open edX、Canvas 等学习管理系统。

但它们普遍没有同时解决以下闭环：

> 来源页面和元素 → 可审计讲解 → 受控提问 → 错因 → 掌握状态 → 间隔复习 → 固定发布版本。

Gemini Notebook 擅长来源约束和引用；Khanmigo强调引导而非直接给答案；Coursera AI依托现成课程；学习管理系统擅长账号、课程和测验记录；OpenMAIC擅长场景化、白板、语音和导出。但这些能力并未自然组合成你所要求的“逐变量、逐公式、逐代码状态、逐图表元素”的可检查教学合同。

### 为什么必须重新定义

**[confirmed]** “多 Agent”“生成更多内容”“生成动画、语音和教学 PPT”本身不等于学习效果。instructional_agents 的论文主要测量课程产物质量和教师修改工作量，而非学生的延迟记忆或迁移能力。OpenMAIC 的架构和功能值得借鉴，但它的多角色课堂与本项目的个人深度自学目标并不相同。

**[confirmed]** 教育人工智能的反证非常重要：一项大学物理随机试验表明，经过严格设计、分步引导、有完整高质量答案支撑的 AI tutor 可以优于课堂主动学习；但另一项近千名高中生参与的现场实验发现，无护栏聊天工具虽然能提高当下练习表现，撤掉工具后的无辅助成绩反而下降。

因此本项目不能把“学生得到答案”误判为“学生已经学会”。

### 推荐的最小垂直切片

第一道建设目标不是全部 72 页，更不是一个学期，而是从 EE680 中选取 **8–12 个代表页**：

- 一页复杂 LaTeX；
- 一组 Kernighan–Lin 伪代码；
- 一页复杂图表；
- 一页普通示意图；
- 一页高度抽象概念；
- 一段代码或算法状态跟踪；
- 一个材料冲突案例；
- 一次中断、恢复和局部重生成。

这一切必须打通：

> PPTX/PDF 导入 → 页面与元素锚点 → ReadWeave 草稿 → 教学讲解 → 确定性验证 → 发布 → 播放 → 提问 → 测验 → 错因 → 掌握状态 → 版本回滚。

### 推荐架构

**[inferred]** 采用两个有边界的系统：

- **ReadWeave**：课程语义、证据、版本、正式讲解、问答、错因、掌握状态、成本、审核和发布的权威来源；
- **Course OS**：文件导入、页面渲染、生成编排、模型调用、确定性检查、实时教学播放器和临时会话。

两者只能通过版本化应用程序编程接口（Application Programming Interface, **API**）交互，不能直接共享数据库表，也不能让 Course OS 写 ReadWeave 数据库。

大型文件采用内容寻址存储（Content-Addressed Storage, **CAS**），ReadWeave只保存哈希、元数据、关系和固定发布清单，不保存大量重复二进制内容。

### P0 不做什么

P0 不做：

- 多 Agent 角色课堂；
- 自动生成整套教学 PPT；
- 全程语音；
- 每页生成教学图片；
- 公开多用户；
- 教师后台和班级；
- 学习管理系统集成；
- 论文高密度分析；
- Kubernetes、Kafka、Redis、独立向量数据库等基础设施。

### 成本结论

按 2026 年 8 月 28 日官方标准价格、短上下文调用、未使用缓存折扣估算：

- **质量型，无补充图片和语音：约 2.31 美元/50 页；**
- **质量型，少量补充图片和语音：约 2.97 美元/50 页；**
- **质量型，大量多模态：约 12.87 美元/50 页。**

这说明模型文本生成本身不是首要成本风险；**无上限重试、全页生成图片、全程语音、重复生成和错误缓存才是主要成本风险。**

### 继续推进的门槛

只有同时满足以下条件，才从垂直切片扩展到全部 72 页：

1. 高风险元素解释覆盖率为 100%，其他必需元素不少于 98%；
2. LaTeX、代码、伪代码、锚点和发布清单的确定性检查全部通过；
3. 人工中位修改时间不高于每页 3 分钟；
4. 质量型路线单份 50 页材料不超过 8 美元硬上限；
5. 延迟测验、迁移题或无辅助解释任务至少一项明显优于当前原型，且无辅助表现不下降；
6. ReadWeave 写入、读回、回滚和部分失败恢复没有数据不一致。

## 2. 已改变的关键判断

### 2.1 OpenMAIC 比预期更值得借鉴，但仍不应成为主项目

**[confirmed]** OpenMAIC 正式仓库为 THU-MAIC/OpenMAIC。其 v1.0.0 于 **2026 年 8 月 27 日**发布，加入持久会话、文件上传、工具与技能、可替换持久化和多模型提供商支持。当前仓库根许可证是 MIT，不再是早期 AGPL；不过仓库内仍有 LGPL-3.0-or-later 的第三方组件。其论文有 arXiv 版本，并发表于 JCST。

它值得借鉴：

- 两阶段“规划—场景内容”生成；
- session、pause、resume、cancel 的状态管理；
- scene/action 式教学动作描述；
- PPTX、HTML、课堂包导出；
- 白板、语音、播放器和交互引擎；
- 导入、渲染和持久化的模块边界。

不应直接照搬：

- 多角色 Agent 对话作为默认教学形式；
- 以生成新教学幻灯片为核心产物；
- 把 Agent 之间的自然语言对话当作可靠工作流；
- 用 OpenMAIC 的持久化模型替代 ReadWeave；
- 把“课堂表演感”误当作掌握证据。

### 2.2 “教授级”不能再定义为“讲得很长”

**[inferred]** 教授级必须被重新定义为一个可验收合同：

- 所有必需元素均被识别；
- 每个元素均有对应解释或明确的省略理由；
- 推导和程序状态可重放；
- 事实来源和模型补充可区分；
- 存在例题、理解检查和迁移任务；
- 学生在撤掉帮助后仍能独立完成任务。

“篇幅长”“术语多”“像教授口吻”都不是质量指标。

### 2.3 多 Agent 从架构原则降级为实验变量

**[confirmed]** instructional_agents 的局部消融实验显示，多 Agent 在其特定课程生产评分上优于单 Agent，但该结果只适用于其提示词、课程生成任务和评分框架，不能证明对本项目或学生学习效果同样有效。其系统也报告了 LaTeX 错误、有限视觉表现和反馈后重新生成等问题。

因此：

- P0 使用一个确定性编排器；
- 模型阶段输出有类型的结构化对象；
- 只有在盲评消融中显著优于简单流水线时，才加入额外 Agent。

### 2.4 来源约束不能等于“禁止教授补充”

**[inferred]** 严格只允许源材料内容，会阻止前置知识、背景说明和必要例子；完全开放模型补充，又会产生无来源扩写。

正确方式是三分法：

- `source_claim`：源材料直接支持；
- `supplement_claim`：外部知识补充，必须明确标记和引用；
- `conflict_claim`：补充内容与源材料冲突，不能静默覆盖。

### 2.5 “实时”应当是渐进发布，而不是直接显示原始模型流

**[inferred]** 原始 token 流无法保证数学转义、结构完整、引用有效或成本可控。

P0 的实时应定义为：

> 页面级并行生成；每个页面通过最低质量门后即可播放；未通过的页面继续生成或重试。

不是：

> 模型生成一个字，前端显示一个字。

### 2.6 ReadWeave 适合承担语义权威，不适合承担一切运行职责

ReadWeave适合保存：

- 课程和学习目标；
- 来源锚点；
- 正式讲解；
- 问答；
- 测验、错因和掌握状态；
- 版本、发布、证据、成本、审核。

不适合直接承担：

- 大型二进制文件；
- 图片和音频缓存；
- 临时转换文件；
- 高吞吐生成任务队列；
- 浏览器播放瞬时状态；
- 模型提供商超时重试。

### 2.7 双栏布局是可接受假设，不是已经证明的最优方案

**[hypothesis]** 左图右文对桌面深度学习有效，但有注意力分裂风险。解决办法不是取消双栏，而是：

- 左侧同一时刻只有一张视觉材料；
- 右侧不重复图片；
- 文字解释可指向左侧区域；
- 不强制自动缩放或自动移动；
- 手机上改为“视觉／讲解／提问”切换；
- 通过实验比较双栏与顺序模式。

### 2.8 全量逐行解释应存在，但不应默认全部朗读或展开

**[inferred]** 机器覆盖层需要逐行、逐变量、逐元素；人类界面需要分层呈现：

- 主讲解；
- 点击展开的逐行解释；
- 推导详情；
- 边界情况；
- 进阶说明。

否则系统会用“全面”制造新的认知负担。

### 2.9 教育标准第一版只保留映射，不追求认证兼容

QTI、LTI、Caliper、xAPI、SCORM 都有价值，但完整接入会把 P0 从个人学习系统变成平台集成项目。应先保持内部规范可映射，再逐步实现导入导出。

### 2.10 多模态是独立产品轨道，不是顺手附加

图片、语音和动画会引入：

- 额外成本；
- 生成错误；
- 版权和许可；
- 无障碍要求；
- 缓存和存储；
- 视觉与文本冲突；
- 更复杂的审核。

因此教学图片和语音进入 P1。

## 3. 真实问题和可测成功标准

### 3.1 真实问题

现有课件通常是教授授课时的视觉提纲，而不是可独立学习的完整教材。学生实际缺少的不是更多文本，而是：

1. **缺失的前置知识和关系**；
2. **从视觉元素到含义的映射**；
3. **公式、代码和算法状态的中间步骤**；
4. **判断自己是否真正学会的任务**；
5. **跨会话、跨材料、跨版本的长期学习状态**。

因此项目的核心工作不是“扩写 PPT”，而是把静态材料转换成一个**可执行、可验证、可发布、可复习的教学表示**。

### 3.2 第一阶段用户和边界

- 用户：项目所有者本人；
- 材料：EE680 和类似工程课程；
- 主要场景：课前补全、课后复习、逐页追问、延迟复习；
- 不优化：教师批量制课、公开班级运营和商业交付。

### 3.3 成功标准

| 维度 | 指标 | P0 门槛 |
|---|---|---:|
| 来源完整性 | 源文件、材料版本、页哈希、锚点可验证 | 100% |
| 高风险覆盖 | 公式、变量、代码段、伪代码行、图表轴和单位 | 100% 或明确人工批准省略 |
| 一般覆盖 | 所有标记为必需的元素 | ≥98% |
| 数学可靠性 | 黄金测试中的 TeX 解析、渲染和往返保存 | 100% |
| 伪代码 | 每一有效行均有说明、前后状态和副作用 | 100% |
| 视觉纪律 | 右栏重复显示教学图片 | 0 |
| 证据纪律 | 来源事实有锚点；外部补充有标签和引用 | 100% |
| 数据闭环 | 写入、读回、版本固定、回滚和重放 | 100% 契约测试通过 |
| 故障恢复 | 超时、重试、取消不产生重复对象 | 100% |
| 人工负担 | 中位修改时间 | **[hypothesis]** ≤3 分钟/页 |
| 人工负担 | 第 95 百分位修改时间 | **[hypothesis]** ≤8 分钟/页 |
| 渐进可用 | 第一页通过最低质量门 | **[hypothesis]** 第 95 百分位 ≤90 秒 |
| 恢复 | 已加载发布版本的会话恢复 | **[hypothesis]** ≤2 秒 |
| 成本 | 质量型 50 页、无补充媒体 | 期望约 $2.31，硬上限 $8 |
| 学习 | 延迟测验或迁移题相对当前原型 | **[hypothesis]** ≥10 个百分点或 ≥0.30 标准差 |
| 无辅助表现 | 撤掉系统后的独立答题 | 不得下降 |
| 错因 | 重复出现的同类误解 | 随复习显著下降 |

这些学习门槛是项目决策阈值，不是来自文献的普适常数。

## 4. 竞品与现有方案原子特征矩阵

符号含义：

- `●`：原生、文档明确支持；
- `△`：部分支持或不构成核心能力；
- `○`：依赖插件、扩展或人工；
- `—`：不是其主要能力。

这些符号只表示**产品自称或代码显示具有该能力**，不表示已经证明学习效果。

### 4.1 核心产品和项目

| 方案 | 来源约束与锚点 | 课程结构/目标 | 页、行、元素级解释 | 测验与掌握 | 实时问答/播放 | 多媒体/导出 | 版本化学习权威源 | 本项目结论 |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| OpenMAIC | △ | ● | △ | △ | ● | ● | △ | 借鉴工作流、播放器和导出，不采用其默认多 Agent 课堂 |
| instructional_agents | △ | ● | △ | ● | — | ● | — | 借鉴课程规划、目标和有界评审 |
| course-builder | △ | ● | △ | ● | ● | ● | △ | 借鉴稳定学习目标 ID 和有限修订循环 |
| Gemini Notebook | ● | △ | △ | ● | △ | ● | △ | 借鉴来源选择、引用跳转和材料问答 |
| Khanmigo | △ | ● | ● | △ | ● | — | △ | 借鉴不给直接答案、分步提示和安全约束 |
| Coursera AI | ● | ● | △ | △ | ● | — | △ | 借鉴与现有课程目标绑定的上下文辅导 |
| Moodle | ● | ● | ○ | ● | △ | ● | ● | 可作为未来集成端，不作为 P0 内核 |
| Open edX | ● | ● | ○ | ● | △ | ● | ● | 借鉴事件和评估模型，不部署整套平台 |
| Canvas | ● | ● | ○ | ● | △ | ● | ● | 借鉴题库、Mastery Paths 和 QTI 兼容经验 |
| ReadWeave 当前 | ● | △ | △ | △ | — | JSON | ● | 扩展为课程语义与学习状态权威源 |
| EE680 当前原型 | △ | △ | △ | △ | ● | — | △ | 保留播放器基础，替换生成和数据合同 |

OpenMAIC 当前支持两阶段生成、场景与 Agent、白板、暂停、缩放、语音、HTML/PPTX 和课堂包输出。其 v1.0.0 具有服务器持久化会话和可替换存储接口，但它没有替代 ReadWeave 的理由。

instructional_agents 具有 syllabus、幻灯片、脚本和测验生成，提供自动、目录、反馈和 Copilot 等模式，采用 MIT 许可证；但论文明确存在 LaTeX 和视觉限制，且其评估重点是产物和修订工作，而非延迟学习效果。

course-builder 的学习目标注册表、连贯性评审、有限修订循环和静态教学播放器最值得复用为设计模式；不值得照搬的是九个 Agent 本身。

Gemini Notebook 当前支持来源约束问答、引用跳转、音频和视频概览、学习指南、测验、幻灯片和信息图，但官方也提醒生成的事实、视觉元素和修订可能存在错误。它仍然不是课程版本、错因和掌握状态的长期权威系统。

Khanmigo 当前公开定位强调引导思考而不是直接给答案。找到的最后一份公开价格支持页为 2025 年 3 月，列出美国学习者/家长每月 4 美元和教师工具免费；**2026 年 8 月实际结账价格未在本次调查中获得决定性证据，标记为 [unknown]。**

Coursera 报告的 9.5% 首次测验通过率改善、更多课程覆盖和使用量均来自公司报告，可确认其自称数据存在，但不能据此认定因果学习效果。

### 4.2 其他开源邻近项目

| 项目 | 主要能力 | 值得借鉴 | 不能证明什么 |
|---|---|---|---|
| ClassBuild | syllabus、研究、幻灯片、测验、音频、SCORM 流水线 | 分阶段生成和 SCORM 封装 | 逐元素解释质量与长期学习效果 |
| course_generator | PDF、DOCX、EPUB、Markdown，多提供商章节生成 | 提供商抽象、章节级生成 | 实时课堂和掌握闭环 |
| Skill-Anything | 学习包、闪卡、测验、间隔复习、YAML 和缓存 | 内容缓存与复习对象 | 宣传中的记忆提升幅度 |
| Microsoft AI/ML curricula | 维护中的公开课程内容 | 人工课程结构和内容基准 | 自动生成系统设计 |

相关代码项目确实存在，但它们大多属于“课程内容生产器”，不应被误认为教授级教学质量的独立验证。

### 4.3 失败分支：inBloom

**[confirmed]** inBloom 是一个应被认真对待的失败案例。该项目投入巨大，试图集中学生数据和教育应用接口，但在隐私、透明度、数据控制权和合作方退出压力下于 2014 年关闭。其问题不是“技术不够先进”，而是系统在收集和共享高敏感学生数据时，没有建立足够可信的治理关系。

对 Course OS 的直接要求是：

- 数据最小化；
- 明确的数据控制者；
- 可导出、可删除；
- 默认个人私有；
- 不把聊天、错因和学习障碍公开到 GitHub；
- 多用户之前先完成权限、审计和保留策略。

## 5. 学习科学到产品行为的映射

### 5.1 基本判断

学习科学不能直接决定具体按钮或模型，但可以排除明显错误的产品行为。

认知负荷、worked-example effect、expertise reversal 和 multimedia learning 支持分块、信号提示、相邻呈现、示例渐隐和按水平调整解释；它们不支持把尽可能多的文字全部堆到右栏。

ICAP、retrieval practice、spacing、interleaving、mastery learning、formative assessment 和 self-explanation 支持主动生成答案、延迟检索、错因驱动复习和掌握后推进；它们不支持把“阅读完成”和“点击完成”当成学会。

productive struggle 支持有限、可恢复的先尝试后讲解，而不是无边界地让学生卡住，也不是立即给完整答案。

### 5.2 映射表

| 理论或框架 | 性质 | 支持的产品行为 | 需要避免 | 验证方式 |
|---|---|---|---|---|
| 认知负荷 | 教学机制 | 分块、渐进展开、主线与细节分层 | 全页一次性解释、重复图片、无关装饰 | 延迟成绩、错误率、暂停/回看模式 |
| Worked-example effect，示例效应 | 教学机制 | 先展示完整解法，再逐渐删去步骤让学生完成 | 只给抽象定义，或永远给完整答案 | 近迁移和远迁移题 |
| ICAP，互动—建构—主动—被动框架 | 参与机制假设 | 要求预测、解释、比较、修正和对话 | 把点击下一页当主动学习 | 学生自行生成解释的质量 |
| Retrieval practice，检索练习 | 强证据学习机制 | 闭卷回忆、先作答再显示答案 | 看答案后点“我会了” | 即时和延迟检索 |
| Spacing，间隔学习 | 强证据学习机制 | 按遗忘和错误记录安排复习 | 一次学完后不再出现 | 7–14 天延迟测验 |
| Interleaving，交错练习 | 条件性学习机制 | 在初步掌握后混合相似问题类型 | 初学阶段随机打乱一切 | 分类和策略选择题 |
| Mastery learning，掌握学习 | 教学组织机制 | 达到标准后推进，失败则针对性补救和重测 | 一次测验决定永久掌握 | 多次尝试后的稳定表现 |
| Formative assessment，形成性评价 | 决策机制 | 用回答证据改变接下来的讲解和题目 | 只收集分数、不改变教学 | 干预前后错因变化 |
| Self-explanation，自我解释 | 学习机制 | 要求“为什么”“这一步依赖什么” | 系统代替学生解释全部内容 | 无辅助口头或书面解释 |
| Multimedia learning，多媒体学习 | 设计原则 | 图文邻近、信号提示、去除无关内容 | 左右重复图、装饰性图片、字幕和旁白机械重复 | 双栏与顺序模式比较 |
| Expertise reversal，专业水平反转 | 边界效应 | 根据掌握状态折叠基础细节 | 对熟练者强制逐行讲解 | 新手与熟练页面停留和成绩差异 |
| Productive struggle，生产性挣扎 | 条件性机制 | 先尝试、分层提示、最后完整解释 | 立即给答案或无限卡住 | 提示层级与迁移表现 |
| Bloom’s taxonomy，布卢姆目标分类 | 分类工具 | 检查目标是否覆盖记忆、理解、应用、分析等层级 | 把高阶动词当成学习效果证据 | 目标—题目对齐审计 |
| Backward design，逆向设计 | 课程生产流程 | 先定义目标和证据，再生成讲解 | 先生成大量内容再补目标 | 目标、测验和内容一致性 |
| ADDIE，分析—设计—开发—实施—评价 | 项目生产流程 | 组织课程开发阶段 | 把流程采用本身当成学习效果证据 | 只能审计流程，不能证明学习 |

**结论：** Bloom、backward design 和 ADDIE 主要解决“怎样规划和生产课程”，不是“这种课程一定有效”的证据。学习效果仍必须通过无辅助测验、延迟测验和迁移任务验证。

- 补充教学图片，但只能切换到左侧；

- P0 不做论文专用提示词；

- `MaterialVersion`；
- `SourceAnchor`；
- `EvidenceLink`；

- `QualityResult`；
- `Release`。

论文分析必须使用独立的 `paper_analysis_v1` 内容类型和独立 harness，不能与 `course_teaching_v1` 混用。

## 7. 架构方案及权衡

| 方案 | 描述 | 优点 | 主要风险 | 结论 |
|---|---|---|---|---|
| A. ReadWeave 插件式单体 | Course OS 全部写进 ReadWeave/Trilium 代码和数据库 | 部署少、表面上只有一个权威源 | AGPL 耦合、升级冲突、二进制膨胀、生成任务拖垮笔记系统 | **不推荐** |
| B. 两个应用、共享数据库 | Course OS 独立前端和进程，但直接使用 ReadWeave 数据库或共用表 | 开发快、查询简单 | 隐式耦合、无 API 合同、数据库迁移互相破坏、许可证边界模糊 | **不推荐作为正式架构** |
| C. 有界上下文＋版本化 API＋CAS | 两个仓库、两个进程、独立数据库，通过 API 交换语义对象；大文件外置 | 清晰权威边界、可测试、可回滚、许可风险较低、未来可扩展 | API 和一致性设计需要前期纪律 | **推荐** |
| D. 微服务和事件流 | 每个生成阶段独立服务，Kafka/Temporal/对象存储/向量服务 | 大规模并发和故障隔离 | 第一阶段运维远大于收益、调试困难、磁盘和内存浪费 | **P2 之前禁止** |

### 推荐 C 的原因

1. ReadWeave已具备证据、版本、任务、成本和审核基础；
2. Course OS需要更高频的任务状态、文件转换和模型重试；
3. 大型媒体不应进入 ReadWeave 数据库；
4. API 边界既方便未来替换播放器，也方便未来替换 ReadWeave；
5. 分离进程和仓库有助于降低许可证与升级耦合，但**不构成法律上的自动免责**。

## 8. 推荐架构和完整数据流

### 8.1 逻辑架构

```text
浏览器
  │
  ▼
Cloudflare Access + Cloudflare Tunnel
  │
  ▼
本地反向代理
  ├── Course OS Web / API
  │     ├── Course OS PostgreSQL：任务、会话、临时编排
  │     ├── Worker：模型和质量流水线
  │     ├── 隔离转换容器：PPTX/PDF/代码处理
  │     └── CAS 文件目录：按 SHA-256 内容寻址
  │
  └── ReadWeave Web / Versioned API
        └── ReadWeave 原生数据库：课程语义和正式学习记录

备份任务
  ├── ReadWeave 一致性快照与 JSON 导出
  ├── Course OS PostgreSQL dump
  └── CAS → restic 加密去重 → 可选 Cloudflare R2
```

### 8.2 权威边界

| 数据 | 权威位置 |
|---|---|
| 原始字节是否为某个正式材料版本 | ReadWeave 的 `MaterialVersion` 和哈希记录 |
| 原始大文件字节 | CAS |
| 正式页、锚点、讲解、问答、错因、掌握 | ReadWeave |
| 正式发布清单 | ReadWeave |
| 当前生成任务状态 | Course OS |
| 模型调用重试和租约 | Course OS |
| 浏览器当前展开面板、缩放和平移 | Course OS 会话 |
| 成本最终审计记录 | ReadWeave；Course OS 提交明细 |
| 缓存、缩略图和临时转换物 | Course OS，可删除 |

“ReadWeave 是权威来源”不要求所有字节都塞进其数据库。其含义是：

> 一个对象只有在 ReadWeave 中有版本、哈希、状态和关系记录，才属于正式课程。

### 8.3 完整数据流

1. 用户上传 PPTX、PDF 或 syllabus。
2. Course OS 计算 SHA-256，检查是否已有相同内容。
3. 文件进入隔离区，执行类型、压缩包、恶意内容和资源上限检查。
4. 合格文件写入 CAS。
5. Course OS 向 ReadWeave 创建不可变 `MaterialVersion`。
6. 隔离转换器生成页面截图、文本、布局、图片区域和代码/公式候选。
7. 每个页面产生稳定 `SourcePage` 和 `SourceAnchor`。
8. 确定性分析器产生 `ExtractedElement`：
   - 公式；
   - 符号；
   - 伪代码行；
   - 代码变量和分支；
   - 图表轴、图例和系列；
   - 图片区域和关系。
9. 学习目标规划阶段把页面和元素映射到学习目标、前置目标和评估证据。
10. 生成阶段按页面产生结构化讲解草稿。
11. 确定性检查先运行，未通过的内容不能交给发布审核。
12. 独立模型评审只检查语义、教学完整性和潜在误导。
13. 只对失败的页面、公式或解释块局部重生成。
14. 通过检查的草稿写入 ReadWeave。
15. 人工或规则批准后，ReadWeave生成不可变 `ReleaseManifest`。
16. 播放器只读取发布版本，或读取明确标记为“未发布预览”的固定草稿版本。
17. 用户提问和测验回答写回 ReadWeave，并绑定当时的发布、页面、锚点和目标。
18. 错因更新 `MasteryState` 和 `ReviewQueueItem`。
19. 下次会话从 ReadWeave读取正式状态恢复。

### 9.2 版本规则

#### 来源版本：不可变

- 文件字节不同，即产生新 `MaterialVersion`；
- 旧页和旧锚点永不重写；
- 页面锚点包含来源版本；
- 页面重新排序不能偷偷复用旧页码语义。

#### 草稿：可编辑

- 草稿从指定来源和 harness 版本创建；
- 使用超文本传输协议实体标签（HTTP Entity Tag, **ETag**）进行乐观并发控制；
- 每次修改产生修订日志；
- 不允许最后写入者静默覆盖其他修改。

#### 发布版本：固定

- 发布清单固定所有对象版本和哈希；
- 发布后不允许原位修改；
- 修改必须产生新发布；
- “回滚”是把活动指针指向旧发布，不是改写历史。

### 9.3 建议 API

统一前缀：

```text
/api/course/v1
```

| 方法和路径 | 用途 | 关键保证 |

## 10. Agent、harness、质量门和失败恢复

### 10.1 推荐生成流水线

P0 不使用自由对话式 Agent 群。使用一个编排器和受约束的模型阶段：

1. `preprocess`：确定性文件处理；
2. `extract`：文本、布局和视觉元素提取；
3. `objective_map`：学习目标和前置关系；
4. `atomize`：生成机器覆盖表；
5. `draft`：生成结构化教学草稿；
6. `deterministic_validate`：公式、代码、覆盖、锚点和 schema；
7. `blind_semantic_review`：独立模型语义评审；
8. `targeted_repair`：只修失败元素；
9. `human_review`：满足触发条件时人工审核；
10. `publish`：固定发布清单。

### 10.2 Harness 必须固定的内容

每次生成保存：

- `harness_version`；
- 提示模板哈希；
- 输出 JSON Schema 版本；
- 模型和快照；
- 提供商；
- 采样参数；
- 工具白名单；
- 检索策略；
- 最大输入和输出；
- 页面邻接上下文规则；
- 成本上限；
- 最大重试次数；
- 最大修订轮数；
- 质量检查器版本；
- 教学合同版本；
- 学习者配置版本；
- 语言和地区。

### 10.3 怎样避免 Agent 互相传播错误

1. 每个阶段只读取不可变证据包和结构化上游产物；
2. 不允许 Agent 通过自由文本相互说服；
3. 评审模型不读取生成模型的自我辩护；
4. 上游低置信度必须显式传递，不得包装成确定事实；
5. 每个事实区分 `source`、`supplement` 和 `conflict`；
6. 最多两轮自动修订；
7. 同一问题连续失败后升级人工，而不是无限自我修复；
8. 页面和元素级重试，不整份讲义重跑；
9. 不允许模型把自己的“已检查完整”当成覆盖证据；
10. 多 Agent 方案必须与单流水线做盲评消融。

### 10.4 检查职责

| 检查类型 | 必须由确定性程序完成 | 可由模型评审 | 必须人工 |
|---|---|---|---|
| 文件类型、大小、哈希 | 是 | 否 | 异常时 |
| 压缩炸弹、恶意 XML | 是 | 否 | 严重异常 |
| 锚点和版本完整性 | 是 | 否 | 否 |
| TeX 解析与渲染 | 是 | 可评语义 | 无法解析时 |
| 代码语法、静态检查、测试 | 是 | 可解释意图 | 有安全或语义冲突时 |
| 伪代码逐行覆盖 | 是 | 可评解释正确性 | 低置信度时 |
| 图表轴、单位和图例存在性 | 是/视觉检测 | 是 | 复杂或模糊图表 |
| 解释是否教学清楚 | 否 | 是 | 抽样或高风险 |
| 外部补充是否可靠 | 部分 | 是 | 来源冲突 |
| 是否允许发布 | 强制门程序执行 | 提供建议 | 指定高风险发布 |
| 成本是否超限 | 是 | 否 | 用户可修改预算 |
| 版权和隐私 | 部分 | 不能最终决定 | 是 |

### 10.5 故障恢复

| 故障 | 行为 |
|---|---|
| 提供商超时 | 指数退避；切换提供商需创建新 stage run |
| 非法 JSON | 一次受限修复；再次失败则页面失败 |
| TeX 无法解析 | 禁止发布；只重生成该数学块 |
| 覆盖缺失 | 生成缺失列表；只补对应元素 |
| 源材料与补充冲突 | 创建 `ConflictClaim`，等待确认 |
| 预算达到 80% | 警告，禁止进入非必要媒体阶段 |
| 预算达到 100% | 原子停止新调用，保存已完成结果 |
| 用户取消 | 标记 `cancel_requested`，当前原子步骤结束后停止 |
| 部分页面成功 | 成功页可进入固定预览，失败页单独重试 |
| 服务重启 | 根据任务租约和事件序号恢复，不重复写入 |
| 同一请求重复提交 | 幂等键返回原任务 |
| 模型拒绝或安全拦截 | 记录原始类别，换用人工或替代流程，不静默丢页 |

## 11. 不同材料类型的讲解合同

### 11.1 所有材料的共同最低合同

每个正式教学单元必须包含：

1. 当前学习目标；
2. 必需前置知识；
3. 来源锚点；
4. 核心解释；
5. 至少一个例子或反例；
6. 易错点；
7. 一次需要学生主动生成答案的检查；
8. 来源内容与模型补充的区分；
9. 机器覆盖记录；
10. 适合当前水平的默认展开深度。

### 11.2 PPTX/PDF 页面

必须输出：

- 页面的教学作用；
- 标题与核心主张；
- 阅读顺序；
- 每个必需元素的解释；
- 页面与前后页关系；
- 教授可能口头补充的前置知识；
- 一个简短理解检查；
- 可展开的深入推导或例子。

禁止：

- 只把项目符号改写成段落；
- 右栏重复展示左栏图片；
- 把无法识别的图表当作装饰；
- 无来源地补写精确数字。

### 11.3 Syllabus

Syllabus 不按普通课件解释。其合同是：

- 课程范围；
- 可观察学习目标；
- 前置知识；
- 模块顺序；
- 评分与考核；
- 课程政策；
- 时间和截止日期；
- 教材与材料关系；
- 目标—考核对齐；
- 不确定或冲突信息。

它主要生成课程地图，不生成逐页“教授讲稿”。

### 11.4 伪代码

每一有效行必须有：

- 行 ID；
- 原文；
- 操作含义；
- 读取的变量；
- 修改的变量；
- 执行前状态；
- 执行后状态；
- 循环不变量或条件；
- 副作用；
- 与复杂度的关系；
- 在一个小例子中的执行轨迹。

Kernighan–Lin 特别要求覆盖：

- 初始划分；
- 外部与内部代价；
- \(D\) 值；
- 节点对 gain；
- 锁定状态；
- gain 更新；
- 累积 gain；
- 最优前缀；
- 终止条件；
- 一轮和多轮的区别。

### 11.5 代码

按逻辑段而不是机械逐字符解释，同时保持变量级覆盖：

- 输入和输出；
- 每个逻辑块的目的；
- 变量定义、类型、形状和生命周期；
- 可变状态；
- 分支和循环；
- 函数调用；
- 异常；
- 外部副作用；
- 时间和空间复杂度；
- 边界输入；
- 一次具体执行轨迹。

只有在安全沙箱内才允许执行用户代码；默认无网络、只读源文件、限制 CPU、内存、进程和时间。

### 11.6 数学

每个数学对象必须包含：

- 符号名称；
- 定义域；
- 单位；
- 维度或形状；
- 在当前公式中的角色；
- 假设条件；
- 推导步骤；
- 代入示例；
- 特殊情况；
- 边界情况；
- 维度或数量级检查；
- 与前后公式关系。

不能只输出“该公式表示……”。

### 11.7 图表

必须覆盖：

- 横轴、纵轴；
- 单位和尺度；
- 图例；
- 颜色、线型、形状编码；
- 每个数据系列；
- 显著趋势；
- 异常点；
- 能直接观察到的结论；
- 需要推断的结论；
- 图表不能支持的结论。

### 11.8 普通图片和示意图

必须区分：

- 可直接观察的组件；
- 箭头、连接和空间关系；
- 流向或层级；
- 标签；
- 被遮挡或模糊部分；
- 模型推断；
- 不确定解释。

## 12. 教学播放器和实时交互

### 12.1 桌面界面合同

左侧：

- 同一时刻只显示一个视觉对象；
- 默认显示原始 PPT/PDF 页面；
- 支持缩放、拖动、复位、全屏；
- 可根据锚点高亮区域；
- 补充教学图只能替换左侧当前视觉；
- 不在右侧再次显示。

右侧：

- 教学主线；
- 正确渲染的数学；
- 逐行和逐变量解释；
- 可展开细节；
- 问答；
- 测验；
- 错因反馈；
- 当前来源、补充或冲突状态。

建议默认可拖动分栏，初始约为 45%/55%，但比例应保存为个人偏好，不写进正式课程版本。

### 12.2 手机布局

手机不采用压缩后的左右双栏，而采用三个模式：

- `视觉`；
- `讲解`；
- `提问/测验`。

在模式之间切换时保持：

- 当前页；
- 当前讲解块；
- 当前高亮锚点；
- 测验未提交答案；
- 视觉缩放状态。

### 12.3 数学渲染

P0 建议：

- 使用结构化 `math_block.tex` 字段；
- 服务器端用固定版本 KaTeX 严格解析；
- 浏览器使用相同版本；
- 保存原始 TeX、规范化 TeX、渲染结果和编译日志；
- 不让 TeX 经过不确定的 Markdown 字符串转义链；
- 不允许解析失败时显示普通文本；
- 不支持的语法必须阻止发布或显式降级为人工确认的替代表示。

### 12.4 实时状态机

#### 上传

```text
created
→ hashing
→ quarantined
→ validating
→ stored
→ extracting
→ anchoring
→ ready
```

任一阶段可进入：

```text
failed_retryable
failed_terminal
cancelled
quarantined_security
```

#### 生成

```text
queued
→ planning
→ atomizing
→ drafting
→ deterministic_validation
→ semantic_review
→ targeted_correction
→ publishable
→ published
```

页面拥有独立子状态，因此第 1 页通过后不必等待第 50 页。

#### 学习会话

```text
idle
→ loading_release
→ teaching
↔ paused_user
→ waiting_for_answer
→ feedback
→ teaching
→ completed
```

提问是教学状态的可恢复分支：

```text
teaching → question_open → answer_recorded → teaching
```

正式问答必须先写入 ReadWeave，再视为成功；前端本地显示不能替代权威写入。

### 12.5 防止学生绕过思考直接要答案

默认回答策略：

1. 先要求学生提交尝试；
2. 识别学生卡在哪一步；
3. 给第一层概念提示；
4. 给第二层步骤提示；
5. 给局部 worked example；
6. 最后才给完整答案；
7. 完整答案后立即要求学生解释关键步骤；
8. 稍后安排无辅助近迁移题。

只有在用户明确切换到“参考答案模式”时，才直接给完整答案；该行为要记录，不能算作掌握证据。

### 13.3 三条模型路线

=\boxed{\$0.27235}
\]

\[

- B：Sol；

\[
\$0.410+\$2.050+\$1.940+\$0.454
=\boxed{\$4.854}

## 14. 安全、隐私、许可证和 GitHub 发布

### 14.1 上传文件是敌对输入

PPTX 本质上包含 ZIP 和 XML，PDF、图片和代码也可能触发解析漏洞。

P0 必须：

- 扩展名、MIME 和魔数联合验证；
- 限制原始大小、页数、解压后大小和文件数量；
- 禁止 XML 外部实体（XML External Entity, **XXE**）和 DTD；
- 防止 ZIP bomb；
- 哈希重命名；
- 隔离目录；
- 无网络转换容器；
- CPU、内存、进程和时间限制；
- 转换进程非 root；
- 输出重新验证后再进入 CAS。

OWASP 明确建议对上传文件执行类型、大小、存储位置和重命名限制，并分别处理服务端请求伪造和 XML 外部实体风险。

### 14.2 Prompt injection

源材料中的文字一律视为数据，不是系统指令。

必须满足：

- 材料不能修改 system/harness；
- 来源解释阶段默认没有工具调用权限；
- 模型不能根据幻灯片文字自行启用网络；
- 外部检索由独立策略模块批准；
- 工具调用参数由程序生成和验证；
- 输出必须通过 schema；
- “忽略之前指令”等内容仍作为课程材料解释，不执行。

Prompt injection 不能靠一句系统提示彻底解决；严格控制必须放在模型外部的权限、数据流和工具层。

### 14.3 服务端请求伪造

P0 建议默认禁止从材料自动访问 URL。

未来开启时必须：

- 只允许 HTTP/HTTPS；
- 解析后阻止 localhost、私有地址、链路本地和云元数据地址；
- 每次重定向后重新校验；
- 禁止 `file://`；
- 限制响应大小、类型和时间；
- 通过独立下载代理，不让模型直接联网。

### 14.4 模型提供商和隐私

当前 OpenAI API 默认不使用客户 API 数据训练模型，但滥用监控日志和 Zero Data Retention（**ZDR，零数据保留**）能力受账户资格和端点限制，不能把“默认不训练”误写成“绝对不保留”。

每份材料应有：

- `sensitivity`；
- `provider_allowed`；
- `external_retrieval_allowed`；
- `retention_class`；
- `export_allowed`；
- `contains_personal_data`。

受保密协议、未公开研究或受限课程材料默认禁止发往未批准的模型提供商。

## 15. Cloudflare 与 VPS 部署

### 15.1 第一版服务

单台虚拟专用服务器（Virtual Private Server, **VPS**）运行：

1. `cloudflared`；
2. Caddy 或等价轻量反向代理；
3. Course OS Web/API；

5. PostgreSQL；
6. ReadWeave；
7. 按需启动的隔离文件转换容器；

### 15.2 Cloudflare

Cloudflare Tunnel 通过服务器主动建立出站连接，避免直接暴露公网应用端口；Cloudflare Access 可以在到达应用前执行身份控制。官方参考架构目前列出免费层可支持最多 50 名用户，足以覆盖个人阶段和早期小范围测试。

推荐：

- `learn.example.com` → Course OS；
- `read.example.com` → ReadWeave；
- 两者均经过 Access；
- 只允许指定邮箱；
- 开启多因素认证；
- PostgreSQL不开放公网端口；
- VPS防火墙只保留必要管理通道；
- Quick Tunnel 只用于临时测试，不用于正式部署。

Cloudflare Registrar 按注册局和 ICANN 成本收费，不加价，并提供 WHOIS 隐私和 DNSSEC；**具体域名价格取决于顶级域和实际结账日，本报告标记为 [unknown]。**

### 15.3 VPS 规格和成本

P0 推荐：

- 4–8 GB 内存；
- 2–4 个虚拟 CPU；
- 80–160 GB SSD；
- 不运行本地大型模型；
- 至少保留 30% 空闲磁盘。

Hetzner 2026 年 6 月生效的官方价示例包括 CAX11 约 5.99 欧元、CAX21 约 10.49 欧元和 CX33 约 8.49 欧元，部分地区美元价和 IPv4、税费另计。

- VPS、IPv4和税费：约 $10–20/月；
- 域名按实际顶级域；
- 备份对象存储通常低于 $1/月；
- 总运维软预算：**$12–25/月**。

- 成本和磁盘测量。

退出条件：

- 高风险覆盖 100%；
- 一般覆盖 ≥98%；
- 中位人工修订 ≤3 分钟/页；
- 无媒体质量路线成本不超过硬上限。

### Gate 3：一份真实 50 页材料和学习实验

交付：

- 前测；
- 即时后测；
- 延迟测验；
- 迁移题；
- 无辅助解释；
- 与当前原型对照。

退出条件：

- 无辅助表现不下降；
- 至少一个主要学习指标达到暂定门槛；
- 学习收益不是仅由答案暴露造成。

### Gate 4：一门课 10 份材料

交付：

- 跨讲义目标；
- 复习队列；
- 掌握状态；
- 课程预算；
- 增量备份和恢复演练。

退出条件：

- 课程级数据没有重复和版本漂移；
- 磁盘、成本和人工审核保持可控。

### Gate 5：P1 媒体和复杂 Agent

每项分别做消融：

- 无图片 vs 少量图片；
- 无语音 vs 语音；
- 单流水线 vs 多 Agent；
- 固定解释深度 vs 自适应深度。

只有盲评或学习测量显示净收益，才保留。

### Gate 6：P2 多用户和 LMS

前置条件：

- 真实教师或学生需求；
- 权限、隐私和删除策略；
- AGPL复核；
- QTI/LTI 兼容计划；
- 多用户威胁模型；
- 可接受的支持和运维成本。

## 18. 最大反对证据、未知项和能推翻推荐的观察

| 当前判断 | 最大反对证据或风险 | 状态 | 推翻推荐的观察 |
|---|---|---|---|
| 教授级逐元素解释有价值 | 可能导致认知过载和阅读放弃 | hypothesis | 分层后仍比简洁讲解的延迟成绩差 |
| 左图右文适合桌面 | 可能产生 split attention | hypothesis | 顺序模式在准确率和主观负担上持续更好 |
| 来源约束提高可靠性 | 会阻止必要前置知识和例子 | confirmed risk | 补充机制仍频繁遗漏关键背景 |
| 模型补充可安全标记 | 用户可能忽略“补充”标签 | hypothesis | 冲突内容经常被当作源事实记忆 |
| 实时渐进生成改善体验 | 质量检查会增加首屏等待 | hypothesis | 第一合格页延迟长期超过 90–120 秒 |
| ReadWeave适合作为权威源 | API、版本和对象扩展可能过于脆弱 | unknown | 维护成本超过独立课程数据库，或频繁破坏升级 |
| 多 Agent不是 P0 必需 | 某些任务可能确实需要专家分工 | inferred | 盲评显示多 Agent在同成本下持续显著优于流水线 |
| 学生会接受提示阶梯 | 用户可能始终要求完整答案 | unknown | 完整答案查看率高且无辅助表现下降 |
| 质量型路线成本低 | 重试和推理 token 可能远高于估算 | hypothesis | 无媒体 50 页稳定超过 $8 |
| 全页原子化可自动完成 | 复杂图表和低质量截图识别困难 | unknown | 元素召回率低于 95% 或人工修正时间过高 |
| 课程讲解能改善学习 | 当前正面 RCT 可能依赖特定物理课程和高质量人工答案 | confirmed limitation | EE680 延迟、迁移和无辅助任务没有改善 |
