# 1. 本轮写作前的最小对照

## 1.1. 术语表的固定载体

术语表只允许一级 BP：每个术语一个独立条目，标题采用正式名称结构，冒号后连续说明含义、当前作用及必要边界，最后给出准确直观比喻；没有父项，没有引导段后的缩进列表，没有“定义／作用／类比”子字段

```markdown
- **交付门禁（Gate）**：在允许交付前核对当前验收、证据和报告是否达到要求的检查步骤；本任务中它决定能否进入正式收口，但不负责保存项目状态；直观来说，它像出厂前的检验关卡，不合格的产品不能直接交付
- **正式收口（Finalize）**：在门禁允许后按同一过程保存最终报告与项目当前状态的操作；本任务中它避免只保存报告或只更新状态，未成功时仍保留未完成事实；直观来说，它像把验收单和对应项目档案一起归档
- **CI 持续集成（Continuous Integration）**：将代码经常合入共享仓库并自动运行已配置构建与测试的开发实践；本任务中只用同一提交的检查结果作依据，检查通过不表示所有未测行为都正确；直观来说，它像每次合入前按既定项目执行的检验流水线，不是包办一切的质量证明
- **API 应用程序编程接口（Application Programming Interface）**：软件提供给其他程序调用的一组功能与规则；本任务中用于读取仓库和发行信息，读取成功与业务判断正确须分别核对；直观来说，它像规定了办理事项与输入格式的服务窗口，而不是整个后台系统
- **IT 迭代单元**：框架用来承载一个稳定目标的本地编号单位；同一目标可以包含多个执行轮次，本地编号没有在当前来源中确认的正式英文全称，因此不猜造展开；直观来说，它像按目标建立的项目文件夹，不是每条消息都新建的文件夹
- **`CURRENT.md`**：保存项目最近合法收口状态的入口文件；本任务应核对它引用的实际报告，不能只根据文件名认定状态有效；直观来说，它像带有原始工单索引的进度牌，不等同于实际执行证据
```

## 1.3. 返修时要拒绝的反例

以下是测试输入，不得复制到正式术语表

```markdown
- CI：持续集成，自动测试
- **Gate／Finalize**：检查和保存
本轮要区分两个动作：
  - 交付门禁（Gate）：交付检查
  - 正式收口（Finalize）：保存记录
```

## 1.4. 语义复核的边界

程序能发现层级、名称排列、缺少解释片段和来源漂移，不能仅凭出现“像”字证明比喻准确；作者必须对实际定义、用途、类比映射和限制给出具体复核，不能填一组 True 冒充理解或独立人类签收
