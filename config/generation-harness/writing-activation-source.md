# 1. 三类规则精简索引

本文件是现行规范的派生提醒，不替代权威正文和合法例外；写作前由实际入口输出本轮相关短句及最小案例，源码变化使旧读取记录失效

## 1.1. 写作规范（Writing）

- **W01**：自行生成的中文正文不用句号，按真实语义使用分号、逗号或分段，受保护原文不改
- **W02**：英文名称按可核实的正式拼写和大小写书写，不猜造官方名称
- **W03**：首次并列名称时，有正式缩写用 ABBR 中文名称（English Full Name），无缩写用中文名称（English Name），未知全称不能猜造
- **W04**：中文叙述中的普通英文采用中文表达（English Expression），机器标识和官方名称不得强行改写
- **W05**：需要定义时说明是什么、当前作用及必要边界并以准确直观比喻收尾；正式术语表固定为一级 BP，其他正文定义保持原规定的相对层级
- **W06**：共同父项下可分别处理的独立项目分别列项，不压成一个混合条目
- **W07**：真实有先后顺序的同级步骤使用连续编号，不用无序列表掩盖次序
- **W08**：父子关系以真实缩进表达，子项只能挂在确实控制它范围的父项下
- **W09**：独立区块使用匹配层级的 Markdown 标题及连续编号，不用加粗或对象冒号伪装标题
- **W10**：分号仅连接需要连续理解的同一行语义，独立步骤、列表项与主题另起结构
- **W11**：空行仅隔开独立段落或块，统一一个空行，不靠多余空行拆散连续列表
- **W12**：引用、用户原文、代码、日志、机器内容及指定格式的受保护部分原样保留，在原文外补充解释
- **W13**：BP 沿问题、需求、决策、任务、验证、证据及状态自然推进，只写实际存在的节点，不堆字段标签
- **W14**：清单保留事前条件、问题及后果、单一承诺和客观判据；执行后更新状态而不把原目标重写成总结
- **W15**：需逐字定位或复制的路径、变量、配置键和代码值用行内代码保真，普通概念不借反引号逃避解释
- **W16**：讲解命令时先给可复制原命令，再按原序解释独立组件，并区分预期作用与实际运行结果
- **W17**：代码注释按单元、参数、逻辑块与必要语句分层，解释原因、边界和副作用，不逐行翻译代码
- **W18**：同块必要同行注释按实际显示宽度统一起始列，只调整分隔空格，不改程序或添加无用注释
- **W19**：不支持注释的机器格式保持可解析，字段说明在外部按原层级逐项对应
- **W20**：重要公式依次给前置解释、完整公式、必要变量说明和关系边界，不虚构单位或验证
- **W21**：行内数学使用单对美元符号界定连续数学关系，不混用行内代码
- **W22**：逐字引用与自己的解释明确分开，长引用用引用块，短嵌入引用用引号并就近标明来源
- **W23**：外部依据按首次出现顺序使用 IEEE 编号、同源复用及可核实书目，不编造出处元数据
- **W24**：只有真实二维比较使用表格，同列同义、宽度充分，表体和下方题注同中心且实际渲染核对
- **W25**：信息图片保真等比例居中，下方同中心题注和必要解说，编号连续且关键内容清晰
- **W26**：结构关系确需图示才用语义正确的原生 Mermaid，默认纵向，配题注解说并实际渲染核对
- **W27**：普通正文不自主加粗或斜体；需要 BP 标题时用 - **标题**：正文，强调不得替代结构或隐藏限制
- **W28**：每个内容单元围绕一个稳定主题，独立主题拆开，只有共同关系需要解释才合并
- **W29**：导航链接使用真实目标和描述性文字，不猜地址；证据和机器 URL 按专门规则处理

## 1.2. 表达风格规范（Style）

- **S00**：先回答用户当前问题，再按需补原因、机制、证据、边界与行动，每层增加真实价值，足够理解后停止
- **S01**：把内部执行过程转为读者能理解的对象、动作、变化、原因、验证和意义
- **S02**：以证实的成果为重心，未知和未完成仅限制其真正影响的结论，不渲染局部缺口
- **S03**：用自然中文表达技术关系与操作，不照搬英文、代码结构、状态标签或 Agent 内部话语
- **S04**：先交代普通读者能跟上的主线，再递进专业内容并就地解释，不用术语代替说明
- **S05**：解释原因时给出条件、作用过程及结果的因果链，不用同义复述或另一个黑盒代替机制
- **S06**：确定性与证据强度一致，未知只约束受其影响的部分，不否定已经成立的结论
- **S07**：句子、段落与总结只保留必要新增信息，足够理解或决策后停止，不为篇幅重复
- **S08**：依用户已知背景及当前目标决定深度，不重复已懂内容，也不预设未解释的专业知识
- **S09**：优先解决此刻的具体问题，不把相邻话题或知识综述放在答案前面
- **S10**：保持独立判断，赞同或反对都以事实和机制为依据，不迎合也不刻意唱反调
- **S11**：继承仍有效的选择、事实与当前断点，更新过时内容，不反复介绍或询问已确认事项
- **S12**：需要取舍且证据足够时给明确优先选择、理由与代价，不原样把判断交还用户
- **S13**：改写与压缩保留原意、立场、语气和边界，只改善准确性与流畅度，不统一成 AI 腔
- **S14**：只补会实质影响当前理解、决策或行动的关键缺口，不因可能有用而扩张新主题

## 1.3. 设计规范（Design）

- **D01**：按主任务组织空间，不把工作台做成说明海报
- **D02**：用中性色建立结构，语义色只承担必要含义
- **D03**：区分内部间距、组间距与独立区域间距
- **D04**：同角色对齐，同角色同规格
- **D05**：文字按语义分层，不靠小字挤满界面
- **D06**：图标、标签与辅助提示共同表达操作
- **D07**：右键菜单围绕选中对象，并提供等价入口
- **D08**：文件树动作必须改变数据，删除必须有恢复语义
- **D09**：双侧栏可调整、可迁移、可找回
- **D10**：反馈必须真实，输入和恢复路径必须保留
- **D11**：菜单、提示、对话框遵守同一焦点与层级合同
- **D12**：文档、列表、画布共享外壳，不共享不相干的数据
- **D13**：适配窗口和输入方式，不靠缩字或裁切掩盖问题
- **D14**：先复用共享实现，再修最小共同根因
- **D15**：用匹配的实际检查证明，不用总分遮盖失败
- **D16**：把反馈沉淀为可追踪设计变化，不堆第二套规范
