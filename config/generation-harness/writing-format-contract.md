# 中文教学正文格式

本文件把当前写作策略中适用于教学页面的格式要求合并为执行规则，来源是同一快照中的 APCF Writing 与 Style 规范，不改变课件事实

## 段落和条目

- 普通中文正文、标题、题目和答案不使用中文句号，行末不留分号；原始引用、代码、日志和表格数据保持原样
- 短段落中确需断开的句子可用中文分号，长段落按语义直接换行；不能把长段里的句号机械换成一串分号，也不能删掉句号后把两个独立判断粘在一起
- 一个自然段只讲一件事；两个能够分别核对的事实、动作、步骤或比较对象必须分行列举，嵌套内容缩进，列表前保留空行
- 同一概念的连续定义保持一个文本块，不拆成机械字段；同一个原因到结果的连续解释也可以成段
- 多个可独立查找的主题都使用同级 Markdown 标题，子主题降低一级；不用“说明：”“步骤：”之类只有冒号标签的伪标题；自行生成的正式小标题使用一致的阿拉伯数字层级编号，写成“1. 标题”“1.1. 子标题”“1.1.1. 更深标题”，原文编号保持原样
- 冒号后只有一个完整说明时可以同行；引出多个独立项目时，空行后用列表分别列出
- 公式后的变量、组分、条件分别说明时也遵守这个换行和缩进规则，不能写成多行无层级的“某符号的定义是”段落

## 名称和定义

- 开头先用日常描述引入问题，不能先抛未解释的术语或符号
- 首次必要术语写成一个列表项：中文名称（有证据对应的英文名称本体）：定义；产品、组织、规范按官方来源核对，学术概念可按原始论文、权威教材或专业机构材料核对通用表达；只有英文拼写而无法确认中英文同指一物时，不能称配对已核实
- 先验知识的每个知识点名都使用“中文名称（有依据的英文名称）：定义”，不用加粗，包括概率等基础知识；无法核实时省略英文但保留未核实状态，不把来源没有写英文误判为不存在英文名称
- 有缩写时放在中文名称前，英文括号只含原名称，不放追加缩写、中文解释或别名；正式名称本体内仍含缩写时保持原名，就近分别说明每个缩写的中文含义、完整英文与本页作用；无法确认英文名称时只写中文，不自行翻译造名
- 定义按本页理解所需连续说明是什么、有什么用、怎样工作、何时适用及易混概念；不机械凑三至五句，确需类比时给出有依据的类比，末尾不加句号或分号
- 定义中的其他术语需要中英文对应，但不递归展开百科；后文优先使用已解释的中文名，保留英文时仍须中文对应
- 普通英文术语的主要实词采用标题式首字母大写，例如“期望值（Expected Value）”；缩写、产品和组织按正式大小写原样保留；大小写正确不能替代真实的名称对应证据
- 数组项目本身会由界面生成列表，不在 priorKnowledge、learningObjectives、misconceptions 的字符串开头重复添加列表标记
- 学习目标数组使用结构相似的“动作标签：对象、必要条件、动作与可观察结果”；主要内容字符串使用顶层 Markdown 列表，每条结论直接回答一个目标，不能用整段摘要或图片布局清点代替
- 变量、代码标识、文件名和逐字原文保持原字符；普通英文词语不能通过反引号规避中文解释

## 公式、代码和来源对象

- 普通文字中的数学符号与关系使用成对的 $...$，独立公式使用 $$ 公式块；不使用反引号代替公式，也不把原始公式改成另一套符号
- 复杂公式放在说明用途的小标题下，其符号、组分、步骤和示范按同一层级组织；本项目按用户要求，每处公式都须就地解释全部符号和组分，前文解释过或相似公式共用变量也不能省略；说明用途、运算顺序、结果含义和成立条件，不只罗列符号名
- 上述逐式解释要求优先于通用写作策略中允许复用符号说明的简写规则，普通概念仍避免无关重复
- 代码先保留原文，另给合法注释副本；逐行解释时有效语句同行注释并对齐，不能合法加注释的格式在原文之外逐行说明
- 图片、表格和引用先保留原对象，再就近解释；原表头、行列、单元格、顺序和数据不能改写，表外说明用中文
- 独占一行且包含等式、求和或分式的公式写成独立公式块；图片和表格的居中、内部横向滚动由界面容器负责，不在生成正文中伪造渲染状态或自行添加危险 HTML

- 图片标题、坐标轴、单位、图例、有效按钮和表格标题等可见标签保留原文，并就近解释所指对象与可支持的判断；内容型链接说明主题、与本页的关系，以及已核对的目标内容，不从链接文字猜测目标页事实

- 仅当来源结构、样式和上下文共同证明资源纯属排版时，不为它另写教学正文；原件及资源记录仍保留，含信息的空白、有效替代文字和加载失败图片不能按装饰处理

- 图片与题注、表格与表题使用同一居中容器；折叠或嵌套区域展开后仍须相对可用区域实际居中，宽表仅在表格内部滚动；未经渲染核对不得宣称已经居中

## 输出前复读

- 逐块核对首次术语与名称证据、内部缩写、可见标签、内容型链接、纯排版资源依据、独立条目分行、正文中的英文、数学定界符和中文句号；机械检查不能代替语义复核或用户接受
- 摘要与题目同样执行以上要求，不能只有完整讲解遵守
- 所有独立结论保留会改变其真实性的条件；明确区分课件原文、演示假设和未确定信息，不通过删条件来缩短句子
- 只返回所请求字段的真实内容对象，不返回 JSON Schema，不输出自评、格式检查说明或流程状态

## 最终 JSON 字段类型

返回一个 JSON 对象，不返回包裹 JSON 的 Markdown 围栏或整篇 Markdown；数组必须是真正的数组，不能把条目列表或整套题写成一个字符串；下面仅演示字段类型，尖括号内容要用当前页的真实教学内容替换，不把示例写入讲义；局部修复只返回 targetFields 指定的键

```json
{
  "chapterBridgeMarkdown": "",
  "learningObjectives": ["<动作标签：对象、条件、动作与结果>"],
  "mainContentMarkdown": "- <结论标签：对应目标的具体答案>",
  "priorKnowledge": ["<中文名称（英文名称）：连续定义>"],
  "fullExplanationMarkdown": "<完整讲解，不能只返回摘要>",
  "misconceptions": ["**错误理解：** <混淆>\n\n**错因：** <原因>\n\n**正确判断：** <结论>\n\n**核对方法：** <方法>"],
  "coverageEvidence": [],
  "questions": [
    {"kind": "multiple_choice", "prompt": "<单选题题干>", "options": ["<选项一>", "<选项二>"], "expectedAnswer": "<选项一>", "explanation": "<独立解释判断依据>"},
    {"kind": "comprehension", "prompt": "<简答题题干>", "options": [], "expectedAnswer": "<参考答案>", "explanation": "<独立解释推理过程>"}
  ]
}
```

示例不是数量配额：目标、前提、易错点和题库按本页实际内容组织；题目必须包含题干、选项数组、答案和独立解释，不能只给待补答案的问题清单

## 本次输出的适用规则复读

在同一次写作中完成下列复读，不输出复读过程，也不新增调用：

1. 数值计算、最大最小项和大小比较必须重新逐项核对 source 中的对应值；计划中的比较结论不是依据，概率最大的取值由概率列比较，不由取值列大小决定；同一结果进入目标、总结、易错点和题目时保持一致
2. 每个 priorKnowledge 数组元素只定义一个必要概念，不把多个定义塞进一个元素；正文使用前面已讲清的定义，只在实际使用处深化机制
3. 自行生成的小标题使用连续层级编号，不用独占加粗标签伪装小标题；原文标题、JSON 字段和固定栏目不被强行改写
4. 并列演算步骤、状态变化及错误选项原因分项解释，不把多个独立项目挤成一串分号；原表的表头和全部单元格原样保留，再在表外讲解
5. 自行成文不使用中文句号；原文引用、原始代码和数据按受保护内容规则保留；术语定义、公式各符号和运算步骤就近讲清

## 字段内的实际写法

fullExplanationMarkdown 中自行编写的主题标题直接使用 `## 1. 具体问题`、`## 2. 具体过程`，真实存在的子主题使用 `### 2.1. 子问题`；编号对应本次实际主题，不固定章节数量，不输出这些占位名称

每处公式后的符号说明逐项列出，例如下面的组织形式；用实际公式中的全部符号与组分替换占位内容，不把公式本身写进反引号：

```markdown
## 1. 本次实际问题

先说明为什么需要计算这个量

$$实际公式$$

- $符号一$：解释实际含义、用途和条件
- $符号二$：解释实际含义、用途和条件

1. 代入本页实际给定的值，记录中间结果
2. 按运算次序完成计算，说明结果能支持的判断
```

存在原始代码时，先完整保留一个原代码块，再给一个完整合法注释副本，最后按实际执行过程说明状态变化；多个分拆代码片段不能替代完整原文；每个错误选项的理由分别列项，不串成分号段

解释数字关系时，先确定比较的究竟是什么量，再用同一量逐项比较；例如概率排序使用概率，期望贡献排序使用取值与概率的乘积，不能互相替代；声称两次抽样独立前要核对抽取机制及条件概率，放回和总体恢复本身不证明独立；原文未说明抽取机制时不追加独立结论，演示假设必须明说并保留在所有依赖它的结论中
