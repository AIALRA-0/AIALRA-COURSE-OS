# 顶层格式规则

本文件是 `human-readable-technical-writing` 的最高优先级格式层，处理面向用户的中文正文、标题、列表、表格外说明、Markdown 题注、代码说明、图片说明、引用说明和混合媒介输出

格式层先决定输出的结构与字符形式，再由文风层、内容层和场景层补充表达；任何格式处理不得修改原文事实、条件、范围、数值、否定、关系、来源或用户明确要求原样保留的材料

## 一、处理范围与修复方式

- `FMT-001` 每次生成或改写面向用户的内容前必须完整读取本文件
- `FMT-002` 格式层适用于普通中文正文、标题、列表项、表格外说明和 Markdown 题注
- `FMT-003` 代码、日志、逐字引用和用户明确要求原样保留的材料属于原样保护范围
- `FMT-004` 格式修复只能修改命中的最小完整单元，不得借局部错误重写无关段落、章节或全文
- `FMT-005` 格式发现错误时必须通过中间件提交并覆盖局部补丁，不能直接覆盖整份输出
- `FMT-006` 格式自动修复最多尝试两轮
- `FMT-007` 两轮后仍无法安全修复时必须保留未修复内容并继续输出，不得因为格式问题卡住交付
- `FMT-008` 格式修复不得改变事实、条件、范围、数值、否定、关系、来源或原样保护材料

## 二、中文标点

- `FMT-009` 普通中文正文禁止使用中文句号
- `FMT-010` 标题禁止使用中文句号
- `FMT-011` 列表项禁止使用中文句号
- `FMT-012` 表格外说明禁止使用中文句号
- `FMT-013` Markdown 题注禁止使用中文句号
- `FMT-014` 原样保护范围内的中文句号必须保持原样
- `FMT-015` 不含独立并列项目的短段落内部，需要断开的中文句号替换为中文分号；含独立项目时先按 `FMT-036` 分行，不因段落短而保留同行
- `FMT-016` 长段落内部需要断开的中文句号必须改为直接换行
- `FMT-017` 句末的中文句号必须删除
- `FMT-018` 句末的中文分号必须删除
- `FMT-019` 句末除中文句号和中文分号以外的标点必须保留
- `FMT-020` 中文分号只用于同一行的紧凑并列或专业术语定义内部的连续说明
- `FMT-021` 中文分号不得代替两个或以上独立项目的换行结构
- `FMT-022` 破折号只有在语义确实需要转折、插入或范围表达时才能使用

## 三、段落、区块与空白

- `FMT-023` 两个或以上不同主题必须分段，至少保留一个空行
- `FMT-024` 不同语义作用的块级结构之间必须保留一个空行
- `FMT-025` 同一个列表和嵌套列表内部不得插入无意义空行
- `FMT-026` 一个短的单主题内容可以不设置标题
- `FMT-027` 两个或以上能独立查找使用的说明区块必须根据内容规模和嵌套关系使用 Markdown 标题分区；介绍对象、怎样操作、如何判断等可以是围绕同一对象的不同区块，不能因为整篇只讨论一个对象就把它们当作短单主题
- `FMT-028` 空白行不得承担隐藏列表层级或伪造段落的作用

## 四、标题与结构

- `FMT-029` `操作：`、`术语：`、`证据边界：`等只有标签并以冒号结尾、实际承担分区作用的伪标题禁止使用；同一行冒号后紧跟真实字段值、术语定义或完整说明时不是伪标题
- `FMT-030` 需要结构化分区时必须使用 Markdown 标题
- `FMT-031` 标题层级必须反映内容的父子关系，不得为了视觉效果跳过必要层级
- `FMT-032` 单主题短内容可以省略标题，不能为了套模板强行添加标题
- `FMT-033` 多主题内容必须使用统一的标题分类体系
- `FMT-034` 标题层级必须随内容规模和嵌套关系自适应，不能固定所有内容使用同一级标题
- `FMT-035` 自然完整句后引出列表、引用或示例时可以使用冒号，但该冒号不得把句子伪装成标题

## 五、并列、列表与缩进

- `FMT-036` 两个或以上独立的定义、步骤、比较对象、事实、原因或动作必须换行输出；同一术语定义内连续解释一个概念的五段逻辑属于一个完整定义，按 `FMT-054` 保持单块；同一原因到结果的连续解释不因有两个动词自动成为并列
- `FMT-037` 并列项目必须按语义层级使用标准 Markdown 列表或等价的块级结构
- `FMT-038` 并列项目前是否出现冒号不影响其必须分行的要求
- `FMT-039` 嵌套内容必须比上一级增加一级缩进
- `FMT-040` 不同语义作用的排比组必须保持独立层级，不能压成同一层；互斥条件下的处理归入各自分支，不与主流程混排成连续编号步骤
- `FMT-041` 单个项目的补充说明可以同行保留，多个独立补充说明必须继续分行
- `FMT-042` 列表内部不得用中文分号把本应独立的项目压在同一行
- `FMT-043` 列表标记、缩进和项目顺序必须与内容语义一一对应；一个来源可以包含多个独立事实，允许分项并保留来源归属，不强制一个来源只能对应一个列表项

## 六、中英文混排与空格

- `FMT-044` 普通正文中的英文名词、英文短语和英文缩写不得单独出现
- `FMT-045` 普通英文名词或短语首次出现必须使用中文名称（English Full Name）形式
- `FMT-046` 带缩写的术语首次出现必须使用缩写 中文名称（English Full Name）形式
- `FMT-047` 中文与拉丁字母、数字、单位之间必须保留清晰可读的空格边界
- `FMT-048` 官方名称、产品名、函数名、变量名、路径、网址和代码标识必须保持官方大小写与字符形式
- `FMT-049` 代码、日志、公式、网址、文件路径和原样引用中的英文可以按原始字符保留；普通英文名称不会因为加了反引号就变成代码标识，仍须中英文配对
- `FMT-050` 括号内普通英文采用标题式大小写，官方名称保持其官方大小写
- `FMT-051` 同一术语在同一输出中必须保持中文名称、英文名称、缩写和大小写一致

## 七、专业术语

- `FMT-052` 专业术语首次出现必须使用 `- 中文全称（English Full Name）：定义内容` 格式；开头概览与结论没有先写术语后补定义的豁免，先用日常描述引入目标，再在首次需要术语的位置定义
- `FMT-053` 带有缩写的专业术语首次出现必须使用 `- 缩写 中文全称（English Full Name）：定义内容` 格式
- `FMT-054` 专业术语定义必须是单行或单个连续文本块，不得拆成多个段落
- `FMT-055` 专业术语定义必须用三至五句连续完整的话依次覆盖“是什么→干什么→怎么干→何时干→如何区分”
- `FMT-056` 五段逻辑分别说明本质定义、功能目的、运作原理、适用条件和常见混淆或不适用边界，不再把旧版历史、词源、上下位及对立概念清单叠加为必填项
- `FMT-057` 词源、别名、历史、学科、分类和例子只在有可靠依据且能解决当前理解困难时补充，不编造不存在的英文、缩写、历史或对立概念
- `FMT-058` 专业术语定义内部出现的术语不需要再次展开定义，但必须显示中文全称（English Full Name）或缩写 中文全称（English Full Name）
- `FMT-059` 专业术语定义内部不得为了分项而插入标题、标签、额外列表或无关空行
- `FMT-060` 专业术语后续出现可以使用已经解释的中文名或中文简称；需要使用英文或缩写时仍按 `FMT-044` 至 `FMT-046` 配齐中英文，不允许首次定义之后把英文或缩写单独使用
- `FMT-061` 未确认官方英文名或缩写时不得自行创造，必须使用自然中文并保留待核对状态

## 八、大小写与专名

- `FMT-062` 普通英文标题式名称的主要实词首字母必须大写
- `FMT-063` 英文缩写必须保持其正式全大写或官方规定的大小写
- `FMT-064` 产品名、组织名、协议名、编程语言名和库名必须保持官方大小写
- `FMT-065` 同一英文名称不得在不同位置任意切换大小写
- `FMT-066` 大小写修复不得改变代码、日志、网址、公式和逐字引用

## 九、公式与 LaTeX

- `FMT-067` LaTeX 公式必须保持原有变量、运算符、上下标、括号、单位和关系符号
- `FMT-068` 行内公式必须使用成对的 `$...$` 定界符，独立公式必须使用独立公式块；新增计算说明中的等式不用反引号冒充公式，真实代码表达式与逐字引用仍按原样保护规则处理
- `FMT-069` 公式前后的中文说明必须与公式分开，不能把公式字符改写成普通中文标点
- `FMT-070` 多个独立变量、条件或推导步骤必须换行并按层级缩进说明
- `FMT-071` 公式中的英文变量和命令属于原样保护范围，公式外的英文说明仍遵守中英文混排规则

## 十、代码与不可注释格式

- `FMT-072` 用户提供的原始代码先按原字符保留，再提供带合法注释的解释副本；新生成的代码不必重复一个无注释副本；以完整功能块为解释单位时使用合法头行注释，以代码行为解释单位时每个可注释有效语句使用同行注释，代码块外说明不能替代合法代码注释；同行注释与对应语句组成不可拆分单元，不为了正文并列规则把注释移到下一行
- `FMT-073` 同行注释必须在同一代码块内始终从同一目标列开始
- `FMT-074` 每个代码块必须独立计算最长可注释代码行宽度 `L`
- `FMT-075` 同行注释标记必须从第 `L+2` 列开始
- `FMT-076` 制表位按四列显示宽度计算
- `FMT-077` 允许因为同行注释对齐增加代码行宽，禁止为了限制行宽把注释移到下一行
- `FMT-078` 空行、纯闭合符和只承担结构作用的括号不添加机械注释，也不参与 `L` 的计算
- `FMT-079` 同行注释只能增加解释，不得修改代码语句、字面值、调用关系和控制条件
- `FMT-080` JSON 等不能合法添加注释的格式不得伪造注释，必须改用逐行解释；只有不能合法添加注释的格式才能使用该回退路径
- `FMT-081` 逐行解释必须与对应代码行保持一一对应，不能合并成无法定位的泛化说明
- `FMT-082` 原始代码、日志和机器可执行内容中的原始字符必须保持不变；注释只能加入单独的解释副本，不能写进标记为原始版本的代码块

## 十一、图片

- `FMT-083` 图片对象必须保留在解释之前
- `FMT-084` 图片必须有准确描述可见内容的替代文本
- `FMT-085` 图片题注必须放在图片对象之后
- `FMT-086` 图片说明必须覆盖整体主题、阅读起点、有效元素、位置、功能、元素关系、支持的判断和证据限制
- `FMT-087` 图片没有显示某项功能时必须明确写无法从图中确认，不得凭空补充机制
- `FMT-088` 图片居中只能在目标媒介和真实渲染证据允许时声明

## 十二、表格

- `FMT-089` 表格必须保留原表头、列、行、单元格、顺序和原有数据
- `FMT-090` 表格适配只能转换外层标记，不得改变表格数据
- `FMT-091` 不得向原表增加“决策提示”等解释列，也不得把解释写进数据格
- `FMT-092` 表格题注必须放在表格对象之后
- `FMT-093` 表格外说明必须覆盖表格用途、列名、单位、允许值或内容范围、行映射、异常格、比较关系和限制
- `FMT-094` 表格单元格中的原始标点、英文、数字和单位属于数据内容，不能为了格式统一而改写

## 十三、引用、日志与原始材料

- `FMT-095` 短篇逐字文本必须使用引用块保留
- `FMT-096` 代码和日志必须使用代码块保留
- `FMT-097` 原始材料的解释必须放在原始对象之外
- `FMT-098` 逐字引用、代码、日志和用户明确要求原样保留的材料不得为了统一格式而改写原始字符
- `FMT-099` 生成结论和普通强调不得伪装成引用

## 十四、流程图与混合媒介

- `FMT-100` Mermaid 流程图源代码必须保持语义、节点、边和方向不变
- `FMT-101` 流程类 Mermaid 默认使用从上到下的方向，用户明确指定方向时按用户要求
- `FMT-102` Mermaid、代码、图片、表格、公式和引用之间必须按语义区块分开
- `FMT-103` 混合媒介说明必须先呈现原始对象，再呈现对应解释
- `FMT-104` 混合媒介中的每个独立对象都必须有可定位的说明，不得用一段泛化文字覆盖全部对象

## 十五、输出前复核

- `FMT-105` 输出前必须逐项检查中文句号、句末标点、并列换行、嵌套缩进、冒号伪标题和主题空白
- `FMT-106` 输出前必须检查英文独立出现、术语首次格式、英文大小写、公式边界和原始对象完整性
- `FMT-107` 输出前必须检查每个代码块的注释覆盖、目标列、结构性豁免和 JSON 逐行解释
- `FMT-108` 输出前必须检查图片题注、表格题注、引用对象、混合媒介顺序和真实渲染限制
- `FMT-109` 复核发现错误时只提交对应字符、词组、句子或列表项的局部补丁
- `FMT-110` 复核结果不得伪造用户接受、事实来源、渲染证据或测试结论

## 十六、图片与表格居中

- `FMT-111` 所有新生成或重新排版的图片对象必须在目标媒介可靠支持居中时使用居中布局
- `FMT-112` 图片题注必须与对应图片使用同一个居中容器，不得只居中图片或只居中题注
- `FMT-113` 多图表格中的每个图片单元格必须居中
- `FMT-114` 原始材料要求逐字保留时不得改写原图片语法，只能在对象外增加居中容器
- `FMT-115` 所有新生成或重新排版的表格必须在目标媒介可靠支持时使用页面居中布局
- `FMT-116` 表题必须与对应表格使用同一个居中容器和相同的居中方式
- `FMT-117` 表格居中只能改变外层排版或对齐标记，不得改变原表头、列、行、单元格、顺序或原有数据
- `FMT-118` 表格可能超过可用页面宽度时，横向滚动必须限制在表格自己的容器内，页面整体不得横向溢出
- `FMT-119` 原始表格要求逐字保留时不得改写原表语法，只能增加外层居中与溢出容器
- `FMT-120` 目标媒介不能可靠支持图片、题注、表格、表题、图片单元格居中或表格内部横向滚动时，必须自然说明对应限制，不得声称已经实现；具备实际渲染证据时再声明最终结果

## 十七、专业术语定义模板

首次出现专业术语时使用下面的结构，其中定义内容保持一个连续文本块，不插入分段或字段标题

`- 中文全称（English Full Name）：定义内容`

带缩写的术语使用下面的结构

`- 缩写 中文全称（English Full Name）：定义内容`

定义内容用三至五句连续完整的话覆盖“是什么→干什么→怎么干→何时干→如何区分”，语义句之间按标点规则用分号衔接，末尾不加中文句号或分号；这五段逻辑构成一个术语定义，不拆成五个子列表；定义内部出现的其他术语不再次展开正式定义，但仍显示中文全称（English Full Name）或缩写 中文全称（English Full Name）

## 十八、标题与语义作用的裁决

聊天中的短单主题回答使用自然段或列表即可，多个独立主题从二级或三级标题中选择一个顶层并保持一致；独立长文可以有一个一级总标题，其下使用二级分区，子主题每次只增加一级

先判断一个文本块是在定义一个概念、解释一个因果过程，还是列举多个可独立使用的项目；定义与因果过程可以连贯成块，真正并列的步骤、比较对象、列说明和行说明必须逐项分行

逐字来源对象本身先保持完整；对它的解释可以按事实、条件或动作分项，只要没有改变来源归属、事实或顺序要求，不能仅凭拆成多个解释项判为错误

下面两种情况用于确定拆分边界，不要求正文照搬例子或章节名称

- “打开盒盖，取出试纸，再合上盒盖”包含三个可单独执行的动作，应写成三个有序步骤；后一步依赖前一步不等于可以挤在同行，示范段落也一样处理
- “盒盖关紧后，外面的水汽较难进入，盒内物品更不容易受潮”是在解释同一个变化产生结果的原因，可以保持连续语句；不能只因为出现多个动词就拆出几个独立事项

独立项目须能指出各自可完成或可核对的结果；后半句只是把前一个动作说得更具体时，不因出现第二个动词就判成第二步；判断冒号伪标题也必须确认它确实承担分区作用，不能仅凭冒号或条件引导短语认定违规

复核普通项目时分别问：是否产生了第二个可完成的动作结果，是否要核对第二项事实，是否需要回答另一个问题；成立时增加同级或子级项目，不能仅以同一流程、同一对象或同一询问人为由继续合并；单个动作的地点、目的及直接解释可以同行，不把它们机械拆开

检查英文不能只看首次定义；定义后可以用已解释的中文简称避免重复长标签，但每次保留英文或缩写时仍须配齐，不能用反引号、括号或“前文已经解释过”取得豁免；原始文件名和真实代码标识保持不变，在对象外解释

开头概览、结尾总结和自行拟写的问话示范仍适用独立项目分行；只有真实逐字引用才保留原来的合并写法，不能用引号为新写的多个问题取得原文豁免

列名说明、各行事实、操作步骤和结论限制承担不同作用，分别形成实际需要的区块，不把它们压成一个长列表；小区块可以合入同一主题标题之下，不要求每个区块都有标题

本文件要求的格式目标必须认真执行，但修复失败不等于停止普通交付；开发评测仍如实记录未遵守项，不能把继续交付记成全部通过
